# ADR-016: التتبع الموزّع (trace_id) + JSONL + Flight Recorder + Zero-Leakage Redaction

- **Status:** Accepted
- **Date:** 2026-11-25

## Context
النظام يعمل عبر 4 عمليات (`Extension → Bridge → Core → UI`). بدون ربط موحّد للسجلات وسياق قبل الخطأ، يصبح تشخيص الأعطال النادرة مستحيلاً، بينما التسجيل غير المنضبط قد يسرّب الكوكيز والتوكنز أو يبطئ التحميل.

## Decision Drivers
- إمكانية تتبع أي حادثة من نقرة المتصفح حتى كتابة القرص بسهولة.
- عدم التأثير على سرعة التحميل (Zero Hot-Path Blocking).
- استحالة تسريب أي سر أو بيان خاص للمستخدم في السجلات.

## Considered Options
1. **وحدة `vortex-observability` من Phase 0:** `tracing` + `trace_id` (UUIDv7) عبر العمليات + كاتب غير حاجب `JSONL` + تدوير 50MB + Dynamic Reload + **In-Memory Flight Recorder** (آخر 2,000 سجل `DEBUG`) + `secrecy`/`zeroize`/`RedactedUrl`.
2. **سجلات نصية بسيطة عند الحاجة** — تعجز عن تشخيص الأخطاء العابرة للعمليات وعرضة لتسريب الأسرار.

## Decision
اعتماد بنية المراقبة والتشخيص الكاملة الموصوفة في §22، وبناؤها في **Phase 0** قبل كتابة المحرك.

## Consequences
- **إيجابيات:** سرعة هائلة في إصلاح الأخطاء، أمان كامل للأسرار، وتجربة تصدير حزمة تشخيص شفافة للمستخدم.
- **سلبيات ومقايضات:** استهلاك ~2 MB RAM ثابتة للـ Flight Recorder — ضمن الميزانية تماماً.
- **التحقق والفرض:** **Zero-Leakage CI Test** الإلزامي يفشل البناء فوراً عند أي تسرب لسر في السجلات.
