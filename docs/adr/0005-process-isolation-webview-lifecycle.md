# ADR-005: فصل Core / UI / Bridge وتدمير WebView2 عند الإغلاق مع ميزانيات زمنية واقعية

- **Status:** Accepted
- **Date:** 2026-11-25

## Context
المتصفح يغلق عملية الـ Native Messaging Host فور إغلاق المتصفح، كما أن إبقاء نافذة WebView2 مخفية في الذاكرة يستهلك 50–120 MB RAM بلا فائدة بينما المستخدم يستخدم برامج أخرى. في المقابل، تشغيل WebView2 من الصفر (Cold Spawn) على Windows يستغرق فيزيائياً ~300–450ms.

## Decision Drivers
- بقاء التحميلات شغالة حتى لو أُغلق المتصفح أو النافذة الرئيسية.
- ذاكرة Idle في الخلفية < 45 MB نموذجياً (وسقف صارم < 60 MB).
- صفر تأخير فعلي في بدء التحميل (0ms Effective Stream Start) حتى أثناء فتح النافذة.

## Considered Options
1. **3 وحدات معزولة:** `vortex-bridge.exe` (< 1 MB للمتصفح) + `vortex.exe` (Core + Tray دائماً في الخلفية) + نافذة WebView2 تُنشأ عند الطلب وتُدمَّر عند الإغلاق للـ Tray، مع ضخ الـ Probe لـ 16 MB في الذاكرة منذ اللحظة صفر، وخيار إعداد اختياري ("الوضع الفوري") لإبقاء WebView دافئاً لمن يملك ≥ 16GB RAM.
2. **عملية واحدة تضم كل شيء وتخفي النافذة فقط** — تستهلك RAM عالية دائماً وتموت التحميلات إذا شغّلها المتصفح كـ Native Host.
3. **بناء نافذة إضافة ثانية بـ Win32 خام في الـ MVP** — يضاعف صيانة الواجهة والـ RTL والثيمات مبكراً (يُؤجل كتحسين اختياري لاحقاً).

## Decision
اعتماد الفصل الثلاثي مع تدمير WebView2 افتراضياً عند الإغلاق، وميزانية **`< 80ms` (Warm)** و**`< 450ms` (Cold)** لنافذة الإضافة مع **`0ms` إهدار في بدء الدفق الفعلي**.

## Consequences
- **إيجابيات:** ذاكرة Idle حقيقية ~15–35 MB، استمرار التحميلات بعد إغلاق المتصفح، صفر ضياع للسرعة أثناء فتح النافذة، وميزانيات صادقة قابلة للقياس.
- **سلبيات ومقايضات:** أول نافذة باردة تستغرق ~350ms للرسم البصري (مغطاة بالكامل بضخ الـ Probe الخلفي).
- **التحقق والفرض:** قياس آلي لـ Cold/Warm Latency واستهلاك RAM بعد إغلاق النافذة في اختبارات الأداء.
